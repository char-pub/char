# 变更验证策略

验证从变更的权威边界出发。纯内容语义先跑 Core、Assembler 或 CCv3 单测与属性测试；跨协议变更同时跑服务端授权、并发与失败路径测试；浏览器交互再跑 Web/Admin 测试和关键 E2E。规范语义需在 Node、浏览器和 workerd 中复核 conformance，但 draft case 运行成功不等于已建立审阅基线。

依赖规则保持 Core 零 IO、纯包与应用之间的方向，管理前端不能反向引用服务端私有实现。CI 还检查类型、构建、依赖边界、分发 bundle 与源一致、密钥泄露，以及独立的代码和依赖安全扫描。Action 分发可将第三方依赖隔离到 vendor，但构建必须验证其中没有第一方或工作区代码；CodeQL 仍扫描第一方源码及其分发代码，依赖清单仍接受依赖审查。分发一致性检查覆盖整个生成目录的新增、修改和删除，不能漏过未跟踪的 vendor 文件。具体脚本、版本和覆盖率阈值以根 `package.json` 与 workflow 配置为准，不在本文重复易变数值。

本地全栈验证可从服务启动和冒烟脚本进入，尤其要确认迁移、API、worker、前端与对象存储一起工作。测试结果应按实际运行范围报告：单测通过不能推断生产外部服务可用，draft conformance 通过不能推断多运行时语义已被人工认可。

涉及镜像、依赖来源或启动可重复性时，已有缓存可运行不证明目标干净环境能取得并构建依赖；应针对变动、失效或存疑的依赖核验实际来源与冷获取路径，并以相应 CI 结果确认，不要求每次清空全部缓存。本地 Compose 与集成测试共用固定上游源码构建的对象存储镜像，避免两条启动路径依赖不同产物；源码构建仍依赖基础镜像和模块来源，不代表离线可用。

跨层 fixture 应由真实生产者生成，或先经过权威 schema 校验，避免手写对象和错误实现互相迎合。关键全栈验证必须检查消费端实际读到的字节：例如上传后刷新仍能读取私有预览，公开发布后公共 URL 确实返回图片；仅断言任务完成或数据库 active 不能证明分发链路可用。

集成测试使用真实 Postgres 和 S3 兼容存储验证事务、权限、迁移与对象行为；外部 GitHub/OIDC/webhook 替身应真实计算 JWKS 签名或 HMAC，不能通过旁路授权来证明协议。时钟与 ID 注入让边界和重试可重现。fixture 使用合成或许可明确的数据，不使用真实非法材料或用户隐私；主站演练需要专门账号与仓库，结束清理。

工作中执行与改动相称的检查，里程碑与最终验收运行 `pnpm ci:all`；CodeQL 和 dependency-review 属于独立 CI，不能把本地命令通过写成它们已执行。要求的检查失败、跳过或无法运行时保持验收待定。测试阈值的当前可执行值以配置为准，不能为了达标降低既定验收标准。开发过程与授权约定见 working-agreements，正式开放的剩余门槛见 release-readiness。

改变模型实际输入时，验收材料保留有序messages、固定Turn/Profile、实际Plan、内容/策略/参与者来源与对应精确摘要；摘要相同与测试数量不能证明语义正确。视角、知情与角色复用要直接检查文本及身份，再把发现转为独立不变量回归。跨 SDK 与 provider adapter 的验证须检查实际序列化请求，核对每个 system 片段、顺序与历史边界均被正确投影，特别防止追加片段被当作替换快照。Session requested 日志只证明组装输入，成功响应只证明调用完成；二者都不能证明 provider 收到完整上下文。无网络投影探针可验证被测构建的转换，但不能冒充此前在线进程的请求证据。

指定人物、故事或领域的 demo 必须独立核对关键经历、关系、处境与抉择是否兑现用户用例，技术链路或保存成功不能替代内容验收；合成 fixture 不得未经对齐替换交付主题，真实素材改编应核来源并区分史实、模拟与获准改写范围，姓名或关键词出现不证明内容保真。带剧情状态或渐进信息的 Roleplay 还须从实际入口验证连续行动、引擎确认的持久后果、条件变化后的信息或选择，以及恢复后的继续游玩；逐步核对消费端呈现、模型上下文与权威状态，确认未满足条件的信息仍受可见性约束。素材字数、开局数量或单次回复成功不能替代这条因果链的证据；未覆盖的体验维度保持待验收。

对白生成、结构化判断与剧情提交分别验收，分别核实际模型路由、思考/输出预算和结束原因。用事先编写的逐回合语义期望对照提案、Core 准入、持久状态和后续上下文，不从实际错误输出反写期望；fixture 覆盖 schema 允许的有效表达，包括以 scene.opening 表达场次内容。对白成功但判定不可用等部分结果，在界面、请求恢复和重启后仍须可辨认。对已约定需玩家确认的承诺，用研究、准备或继续修订但尚未决定的反例检验提案/确认分离，以及过期、幂等、失败和撤回后的边界，不以换模型或最低回合数替代。

持续会话的性能验收使用真实格式、完整校验的累计事件日志，记录受测轮数、派发数和耗时，比较长度增长后的成本与状态/失败语义。减少同次折叠中的重复验证可以复用已验证的不可变前缀，外部输入与重新载入仍须完整校验；不以持久或跨信任边界缓存替代来源验证。结论限于已测负载，离线派发耗时不能推断在线模型质量、浏览器容量或未测规模，失败样本须保留。

跨仓演练先按用户最新指定目标核对消费者 checkout/HEAD、启动命令、profile 实际解析的模块路径与构建来源；历史目录记录与 SDK 校验不能替代这层归属验证。目标更换后须从正确入口复验，旧截图或缺失能力结论不能直接沿用。外部消费者用不可变tarball、manifest与真实安装locator验证公共compiled入口，不用跨仓source alias。历史fixture由实际旧SDK产生并固定原bytes；捕获前核实际安装来源，不能用新包重写旧证据。新版本日志通过不代表所有历史兼容。

mock浏览器与真实fullstack使用隔离构建目录，避免API配置字节相互覆盖；固定数据库的全栈runner串行。外部Harness验收采用显式独立配置，不把缺checkout静默skip成通过，也不令默认平台测试强依赖外仓。截图必须实际查看，生成的浏览器脚本须真正执行或解析，HTTP200不是交互正常证明。

交付“已启动、可以使用”时，应从用户实际采用的普通启动入口，在当前宿主执行一个代表性业务动作并核持久结果；health200只证明进程存活，带专用seed的隔离测试不证明普通入口具备真实默认内容、精确pin或授权配置。验证还要覆盖实际可见交互：新标签页调用返回不证明用户能继续，DOM存在不证明深色宿主下透明背景的文字可读。使用可见控件的实际点击与已查看截图核对导航、标签、状态和内容；独立页面的前景/背景不能依赖未知宿主默认值。只验证该入口承诺的能力，未调用模型时不把作者开场或Session创建称为在线生成成功。

完整ci:all失败后的分项修复须分别记录，不能拼接成同一次全绿；最终验收以冻结后的实际命令终态为准。llmdoc路由/语义校验与源码测试是不同门槛，元数据指纹也不能在dirty映射源上冒充正式同步。

知识新鲜度与路由覆盖度分开核验：零impacted只说明已有映射没有漂移，不能证明baseline以来的未映射路径已经审过。应逐项确认语义owner或可重建理由，对独立叶实现补精确路由并逐文件验证，不能用父入口、批量命中或宽glob替代。全体owner与变更归属核验完成后才推进全局baseline；用户明确保留的本地dirty如实报告，不靠隐藏源码或刷指纹清数字。

CodeQL分析任务成功只说明扫描执行完成；告警对应的结果检查仍可能失败。应分别核对分析与结果门槛，再报告安全检查是否通过，不能把本地回归或分析job的成功替代实际结果检查。
