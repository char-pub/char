# 内容与发布完整性

checkCreation 检查单件定义，checkDraftBuild 与 checkPublish 复用完整内容构建与纯检查。前者严格要求 draft-build origin，不伪造 Release/label；后者要求发布身份并检查 Registry 提供的状态快照。Core 不查数据库或授予权限，真实 worker 必须重新构造可信快照，不能用预览成功代替发布判定。

检查完整 CreationArtifact 的聚合 lock/meta/assets/capabilities，包含当前内容、模块、锁定 assembly、固定 default_policy、作者测试外部依赖与历史派生来源。执行时未选中的策略或来源仍会随产物分发，不能只检查 IR 或当前 preset。所有嵌套发布来源必须是真实 Release 身份。

每条依赖必须精确 pin，实际内容图及各历史来源图分别维持单版本，跨域允许同 ref 不同发布版共存。public 分发的完整闭包都必须可公开，不能从授权读取私有依赖推出公开再分发权。tombstone 和命中黑名单拒绝；yanked 按读取/依赖规则保留警告，但新派生入口另要求 active source。

许可按具体操作判断：修改根定义需允许改编，原样复制资产需可再分发，未改的 ND 依赖不能被统一标为 modified。资产 ready 只证明处理状态；平台字节的 ownership/grant 由 Registry 另验，linked 声明不能授予 mirrored CAS 读取权。

作者测试由 worker 在 active 前按完整精确输入执行，失败不得发布、不得自动接受新期望。能力要求要明确分发；实验能力的作者确认是创作 UI 行为，不扩大服务端授权或豁免内容门禁。

同一作品/label 对相同内容可幂等返回，冲突内容失败。诊断保留稳定 code/subject，并提供问题与修复方向；自然语言建议不构成更改校验规则或自动修改作者内容的授权。
