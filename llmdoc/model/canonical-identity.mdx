# Creation 的规范化与身份

Creation 是可编辑的语义内容，Release 是一次不可变发布，label 是人在同一 Creation 下选择的名称，不承担 SemVer 的范围解析。引用发布内容必须锁定精确 Release；`@namespace/name` 表示作品身份，而内容 digest 表示字节级可核对的语义快照。公开规范仍处草案状态，修改规范契约须同时核对可执行 schema 和兼容性影响。

规范化先把字符串变成 Unicode NFC、统一换行、去掉行尾空格，再严格校验 schema；未知字段和非纯 JSON 值应失败。等于默认值的字段和空的可选集合被省略，随后用 JCS 序列化并计算 SHA-256。fragment digest 不含自身 digest 字段；semantic digest 基于把 fragments 转成 `(id,digest)` 列表后的 manifest。这个列表保留声明顺序，因为顺序会改变最终 Context IR；对象键顺序和格式空白则不应改变 digest。

九类 Creation 共享身份与发布契约。Preset 必须声明 `policy`，Prompt Module 必须声明 `prompt_module`；两者与 Creative Truth 分开，不能包含 Creative fragments、内容依赖、绑定槽、参数、cast、开场或 context assets，展示资源不成为模型输入。Creative `instruction` 仍是作者的扮演说明。策略块使用稳定 ID 和字面文本，不执行变量或脚本；复用通过精确锁定的 Module 导入表达，块本身没有独立 Release。

规范化 policy、prompt_module、Scenario assembly 与作者 assembly_tests 都参与作品 semantic digest；块、导入、布局和测试的声明顺序有语义，不能排序后计算。省略启用默认值与空预算集合，不省略禁用值；没有新增配置的旧作品摘要保持兼容。Preset 布局必须完整且不重复；Module 不拥有布局、预算或运行能力。结构校验不能替代块 ID 等语义约束。

Canonicalizer 是身份判定的单一实现。签名、发布、锁定图和 Diff 必须使用同一套规范化结果；如果源码和公开规范不同步，先判断该修复实现还是修订规范，不能把偶然的当前行为直接宣布为标准。
