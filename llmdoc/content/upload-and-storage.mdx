# 内容寻址存储与上传

存储把公开分发、私有内容、待处理上传和证据分在不同权限边界。客户端只取得短期、受范围限制的上传 URL；获得 URL 或完成 PUT 不代表资产已获准引用。worker 重新读取对象，核对 digest、类型和像素限制，对图片重编码并清除元数据，再把结果写入 CAS。只有 `ready` 资产能进入发布内容，`processing`、`rejected` 和 `quarantined` 都不能被当作可用资源。

公开 URL 与私有签名读取具有不同可见性。原始上传、导入原件和隔离证据不能经公共桶暴露；清理和保留周期要在成功迁移、引用关系及审计需求之后执行，不能仅凭上传完成删除原件。

处理后的上传最初仍在私有 CAS。草稿引用了 digest 或上传达到 ready，并不代表公共对象已经存在；公开发布负责把解析结果实际引用的 mirrored 资产复制到公共存储。linked 资产仍由外部来源提供，不能当作本地 CAS 对象复制。

当前 worker 组装注入的是 `noopScanner`，因此不能声称上线前自动 CSAM 扫描已经成为发布保证。实际命中、举报或下架由独立处置流程承担；把真实扫描器接入时要重新审阅 quarantine 到 ready 的状态转换。真实 provider 暂不可用时须保持 processing 并重试、告警，不可自动放行；积压危及运行时暂停上传。

HTTP Source 和 linked URL 是声明性来源，不应在 Registry 中无条件主动抓取任意地址；新增抓取能力会引入独立的 SSRF、重定向、大小和内网访问边界，必须重新设计。对上传只信任服务端读取与净化结果，不信任扩展名、客户端 MIME 或请求里自报的 digest。
