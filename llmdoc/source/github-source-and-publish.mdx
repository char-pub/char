# GitHub 来源与发布信任链

GitHub App 绑定使用不可复用的数字仓库及 owner 身份，不能只靠可改名的仓库路径。转移或所有者不一致时冻结来源，待重新确认后再恢复。webhook 验证原始请求字节的 HMAC，按 delivery 去重；push 同步来源状态，不自动发布 Release。

Publish Action 在允许的 push、workflow_dispatch 或 release 工作流中计算本地摘要并申请 OIDC token；PR 事件不得取得发布路径。OIDC 证明的是受约束的仓库工作流身份、ref、sha、事件和 token 新鲜度，不证明运行的 Action 源码一定可信。Registry 校验这些声明和重放标识后，用 GitHub App 权限在该 commit 重新读取源文件，按同一项目解析算法重算 digest。Action 提交的摘要只是比对值，不是最终内容权威。

来源验证成功后进入普通 Revision 与异步发布流程，仍接受 Registry 的权限、依赖、资产和黑名单检查。修改 Action 与服务端任一侧算法时需共同验证 digest 一致和失败重试。
