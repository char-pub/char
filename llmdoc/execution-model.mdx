# 执行模型与权威边界

char.pub 发布静态、可组合的创作定义，并提供创作、协作、发布和开放消费环境。Character、World、Lorebook、Relationship、Scenario、Persona、Style、Preset、Prompt Module 共用 Creation/Revision/Release 生命周期。Scenario 可声明多角色、可选分支、条件、选项和结局；Story 是作品内部定义，不另建一个 Experience 平台对象。静态内容不仅是提示词，还包含可寻址资料、角色实例、状态规则与能力声明。

Core 持有规范化、精确身份、组合解析、Story 纯求值和发布纯检查；不做网络、数据库、文件 IO。Assembler 消费完整 CreationArtifact、Profile 和 Turn，负责安全视角、目录、选择计划、资料正文与最终消息。Runtime 持有真实 Session、模型、判定服务和执行时机。自由聊天本身不自动确认剧情；平台不代理聊天流量，也不承担通用 Agent/Workflow Engine。

Preset 管策略、选择约束和消息布局，Module 复用字面策略块，Style 属于创作内容。完整产物严格按 content/preset/prompt-module 分型；内容构建必须有锁定 assembly 或精确 default_policy，不再保留无策略的旧组装回退。能力声明与真实语义一起分发，消费者必须明确支持、降级或拒绝，不能靠忽略未知字段冒充兼容。

Registry 持有真实身份、授权、资源状态和持久生命周期。发布 worker 只从不可变 Revision、固定依赖与默认策略重建，并在 active 前重新检查授权、许可、资产、黑名单及作者测试。Web 的真实 dbld 构建是有时限、私有、可撤销的检查与预览对象，不是 Release；离线 local-build 也不能冒充 Registry 草稿或依赖 pin。

平台提供受限 OAuth 委托：独立消费者读获授权内容、创建本人新稿及提交投稿，不能由此编辑既有稿或发布。RuntimeLaunch 只交接精确来源、锁、开局、locale 与视角，不携带凭据或真实聊天，不代替 Runtime 自己的 OAuth 和用户启动确认。合成预览文件、Ending 投稿与 from_play 续作是各自独立、明确确认的回流，不能把运行态自动写入作者内容。

跨仓 SDK 通过不可变打包物验证真实公共入口和实际字节，不能用主仓 source alias 代替外部消费。独立 Harness 的模型、Session、持久日志和应用配置由其仓库持有；此仓只拥有公开契约与消费者验收边界。历史恢复证据不等于承诺所有历史兼容。

公开 API、管理 API 与 worker 采用独立进程与授权边界。迁移以 owner 权限单独执行，应用使用受限角色；迁移失败禁止放流。客户端 schema、隐藏按钮和本地测试均不能替代服务端授权。规范与决定是语义依据，具体命令和依赖方向由仓库脚本及规则约束。
