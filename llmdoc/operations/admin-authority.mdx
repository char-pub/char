# 管理权限与操作确认

管理 API 由独立进程承载，公开 API 不挂管理路由。每个管理请求先验证 Cloudflare Access JWT 的受众与身份，再以邮件允许名单映射数据库用户和 staff 角色，由 `adminRoute` 按能力矩阵判定。管理 SPA 的角色隐藏、按钮禁用与 reason 表单改善操作体验，但不能成为授权或审计的权威。当前管理路径不使用应用内 GitHub OAuth 会话或 Better Auth admin 插件。

有状态操作要求明确理由；法律处置还需关联 case。高影响动作按能力和范围走双人确认或冷静期，通常由另一名合格员工批准；只有发起时确实没有其他合格员工，才允许冷静期满后的受审计自确认，不能用等待代替原本可用的第二人。服务端在执行前重新检查身份、状态和批准条件，不能凭前端已显示“可执行”跳过。写入动作与审计记录须保持事务一致。

角色字段在后端、共享协议和前端展示之间同步；修改能力矩阵时同时检查直接 HTTP 调用的拒绝路径及 UI 呈现，尤其是受控下载和下架。

管理端用于处置和治理，不编辑 Creative Truth、不参与创作，也不模拟用户登录。当前理由最少十个字符；超过五十个 Release 的下架、CSAM 用户解封、移除 owner 与 namespace 转移属于四眼场景。单人例外的冷静期为二十四小时，以发起时记录的合格人员状态约束；能力、范围和主体在执行时仍须重验。首次 owner bootstrap 与紧急恢复是不同工作流。
