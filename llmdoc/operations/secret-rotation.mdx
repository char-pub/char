# 密钥轮换

用于定期轮换或疑似泄露。密钥只进入受控环境、Railway variables 或 Cloudflare secrets，审计只记名称、操作人、原因，不记值。怀疑泄露立即处置，不等低峰或提前公告，并评估已发生的异常访问。生成格式以环境 schema 为准，不能统一套用任意长度：访客 HMAC 和法律加密密钥须解码为恰好 32 字节。

单 production 没有 staging。先本地校验新配置格式；支持双值/双凭据的系统按“加新保旧→部署→真实冒烟→确认传播→撤旧→再次验证”切换，不支持窗口的凭据需协调中断。provider 窗口以其当时能力为准，不能假设 OAuth、Turnstile 都支持并存。每次轮换保留受控记录，异常时在仍安全的旧值窗口内回退。

| 凭据 | 切换与验证 |
| --- | --- |
| 源站共享密钥 | 定期基线 90 天。旧值写 PREVIOUS、新值写当前并先部署后端；再更新 Cloudflare X-Origin-Auth，核对旧值窗口及经边缘请求；清 PREVIOUS 后部署，旧值应返回 403 origin.forbidden。避免在命令输出暴露值。 |
| R2 | 定期基线 90 天。按现有桶范围和最小权限建新凭据，证据桶与分发桶分离；逐服务更新，验证上传及 private 签名读取，再撤旧。admin 证据读取权限须按现实现核对，不能照搬旧权限表。 |
| GitHub App | 新私钥与旧私钥并存，更新后通过对账实际取得 installation token，再删除旧私钥。webhook secret 使用 PREVIOUS 窗口验证新旧签名后撤旧。 |
| OAuth、Turnstile、SMTP | 按 provider 要求切换，分别验证真实登录、挑战、邮件；SMTP 支持时先建新后撤旧。 |
| BETTER_AUTH_SECRET | 年度或泄露轮换基线；预告可能重新登录，部署后验证会话与登录影响，必要时显式吊销会话。个人 Token 的 sha256 存储不依赖此 key，不会自动吊销；泄露时另行处置。 |
| GUEST_HMAC_KEY | 平时不轮换。泄露后更换会令同邮箱下次验证获得新的 guest ID，已有访客会话不自动失效；评估攻击者用候选邮箱枚举旧 hash 的影响。 |
| 数据库口令 | 协调 api/admin/worker 全部连接与重启，核对迁移凭据与应用最小权限，避免部分服务仍用旧口令。 |
| LEGAL_ENCRYPTION_KEY | API 加密和 admin 解密须共用同一值。密文没有 key ID，当前解密只接受单一 key；不得直接替换。先设计并验证历史数据重加密、迁移和备份恢复，再同步切换两服务，确认旧请求仍可解密。给 API 单独生成新 key 不是修复。 |

轮换后调查日志、截图、CI 输出或第三方服务的泄露根因，补回归与防护。数据库/R2 等凭据已被利用时转入数据泄露响应，不能仅换 key 就宣告结束。
