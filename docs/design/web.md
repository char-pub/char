# char.pub Web 重新设计（v0）

> 状态：已实现，2026-09-23。功能拆分、操作路径、UI 方向和设计稿已确认，第 10 节的实现顺序已全部完成（决策见 DECISIONS D-156，进度见 goals/v0/PROGRESS）。
> 设计稿：[`web.pen`](web.pen)（Pencil）。品牌来源：`vendor/brand-assets`。
> 相关文档：[架构](architecture.md) · [安全](security.md) · [Admin](admin.md)。

---

## 1. 为什么重做

现有 web 的功能基本覆盖了 v0 范围，一共 16 条路由。问题主要在结构和视觉两方面：

1. **视觉与品牌脱节**：页面走的是"图书馆目录卡片"风格，暖纸底、朱红印章、衬线标题、横线纸纹。品牌是冷调的 Sand / Night / Ink，加上橙、紫、蓝三个扁平节点色和几何无衬线字标。现在只有 logo mark 和 favicon 接入了品牌资产。
2. **作品相关页面各自独立**：作品页、预览、对比、贡献是四个互不相连的页面，只靠"← 返回"链接往回走，用户不知道自己处在作品的哪个部分。
3. **有能力没入口**：服务端已经支持 yank、GitHub 仓库绑定、namespace 改名和 namespace 信息，web 上都没有入口。举报入口在上线前必须可用，目前也没有。
4. **底座太薄**：只有 6 个 UI 基础组件，19 个原生下拉框各写各的样式。没有 toast、骨架屏、全局错误兜底，也没有移动端导航。
5. **"危险"和"强调"是同一种颜色**：删除类操作和品牌强调色都用朱红，视觉上分不开。

重做的目标：保留已验证的流程和规则，重新组织信息架构，统一组件体系，视觉向品牌对齐。

### 1.1 已确认的决策（2026-09-23）

| 事项 | 决定 |
|---|---|
| 范围 | 全部做：重组信息架构、换成品牌视觉、统一组件；补上服务端已支持但 web 缺失的功能；服务端缺的接口（公开举报、拒绝理由字段、按 @namespace 查找用户、搜索按 namespace 过滤）也一起补 |
| 作品页结构 | 合并成一个外框加标签页；版本对比并入 Versions，旧的 `/diff` 地址重定向过去 |
| 视觉基线 | 向品牌对齐，浅色为主：默认 Sand 底、Ink 文字，深色用 Night；字体换成和字标接近的几何无衬线。取消之前"配色与字体暂不改动"的限制 |
| 界面语言 | 只做英文，排版给中日文留出长度和换行空间，以后再接 i18n |

## 2. 用户与目标

| 角色 | 在 web 上要完成的事 | 频率 |
|---|---|---|
| 访客（匿名） | 找作品、看懂作品（评级、依赖、许可）、预览上下文、下载 IR / CCv3 | 最高 |
| Runtime 开发者 | 按版本锁定、对比版本、下载 | 高 |
| 创作者（不懂 Git） | 新建或导入 → 编辑 → 发布；管理版本；审阅贡献 | 高 |
| 贡献者（登录用户或验证访客） | 在别人的作品上提修改、跟踪状态 | 中 |
| 技术作者 / Agent | 管理 Token、绑定 GitHub 仓库；主要工作在 CLI / API 里做 | 低 |
| 举报人 / 权利人 | 举报作品、找到内容政策和联系方式 | 低，但上线前必须可用 |

员工管理在 `admin.char.pub`，不在本文范围。

**不做**：聊天界面、`Open in <Runtime>` 按钮、站内通知、付费、语义搜索。

## 5. 关键操作路径

每条路径都是设计稿和 E2E 要覆盖的走查线。括号里写的是它落在哪个页面。

**J1 访客：找到并使用一个作品**
首页或顶栏搜索 → 探索（筛选类型 / tag）→ 作品 Overview（看评级来源、依赖、许可）→ Context preview（看哪些内容会进上下文）→ 下载 IR 或 CCv3。

**J2 Runtime 开发者：锁定并比较版本**
作品 → Versions 标签 → 选两个版本对比（评级和许可的变化要高亮）→ 下载某个指定版本。

**J3 新创作者：从零发布一个角色**
Sign in → Create → 第一次使用先注册 @namespace → 选 Character、填名字 → 编辑器填基本信息（名字、简介、开场白、头像）→ Publish（版本号、可见性）→ 发布报告 → 作品页。

**J4 导入角色卡**
Create → 导入 → 上传 PNG / JSON / CHARX → 导入报告 → 确认评级、权利、许可 → 编辑器 → Publish。

**J5 组合作品**
编辑器 → More options → 依赖 → 搜索并选中一个 World 或 Lorebook、选版本、选 Core / Recommended → 右侧检查栏没有错误 → Context preview 确认效果 → Publish。之后依赖升级时，用 Versions 对比看变化。

**J6 登录用户提交贡献**
作品 → Contributions → 提修改 → 改文本、评级、标签，填标题并确认授权 → 提交 → 贡献详情（查看状态、撤回）。

**J7 访客提交贡献**（作品允许任何人贡献时）
同 J6；提交前先填邮箱、过 Turnstile → 打开邮件链接 → 自动回到提交页 → 提交。

**J8 所有者审阅贡献**
我的作品（看到待审数）或作品的 Contributions 标签 → 贡献详情 → 逐项确认敏感变更 → 接受（合并进草稿）或拒绝 → 编辑器 → Publish 新版本。

**J9 所有者维护作品**
作品 → 溢出菜单或 Versions → Yank 某个版本（填原因）；作品设置 → 调整贡献开放度、邀请贡献者、绑定 GitHub 仓库。

**J10 账户设置**
头像菜单 → Settings → 打开成人内容（确认满 18 岁）/ 创建或吊销 Token / 修改 @namespace。

**J11 举报**
作品溢出菜单 → Report → 选原因、写说明（匿名用户要过 Turnstile）→ 提交确认。

## 7. UI 方向

设计稿在 [`web.pen`](web.pen)，画板有 Foundations、Components、Home、Explore、Creation · Overview（浅色和深色）、Editor。

### 7.1 视觉原则

- **扁平、边框分层**：卡片和面板不用阴影，靠 1px 边框和底色区分层级。阴影只用在浮层上（菜单、对话框、toast）。这和品牌"不用渐变、发光、阴影"的规则一致。
- **一个区块只有一个主操作**：主按钮是橙底加 Ink 文字，每个区块只放一个。橙底配白字对比度不够，所以文字用 Ink。
- **颜色有固定含义**：
  - 三个品牌节点色对应三种作品类型：橙色是 Character，紫色是 World，蓝色是 Lorebook。卡片、徽章、依赖列表、token 占比条都按这个规则着色，用户看到颜色就知道是哪类作品。
  - 蓝色同时用作链接色。
  - 危险操作用单独的红色（`danger`），不再和强调色混用。
  - 评级：General 绿、Teen 琥珀、Mature 浅红、Explicit 实心红。
- **标识符用等宽字体**：`@ns/name@label`、digest、fragment id 一律用 JetBrains Mono，和正文明显区分开。
- **品牌素材原样使用**：logo mark、字标和横版 lockup 直接引用 `vendor/brand-assets` 里的文件，深色主题换成 dark 版本，不手绘也不改色。

### 7.2 Token

| 类别 | 取值 |
|---|---|
| 页面底色 | Sand `#F8F7F4` / Night `#171B22` |
| 卡片底色 | `#FFFFFF` / `#1E232C` |
| 文字 | Ink `#0F172A`，次要 `#475569`，弱化 `#64748B`；深色主题下对应 `#F8FAFC` / `#A7B0BE` / `#808B9B` |
| 品牌色 | Orange `#FF6B3D`，Purple `#8B5CF6`，Blue `#2563EB`。用作文字时换成加深版本，保证对比度 |
| 字体 | Plus Jakarta Sans（界面和标题），JetBrains Mono（标识符）。都用 `@fontsource` 自托管，因为 CSP 不允许第三方字体 CDN |
| 圆角 | 6（小标签）/ 8（按钮、输入框）/ 12（卡片）/ 16（面板、对话框）/ 全圆（徽章） |
| 间距 | 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64；内容区最大宽度 1200，桌面边距 32，移动端 16 |

## 10. 实现顺序

每一步都是一次独立提交，单次改动控制在 2000 行以内。

1. **基础层**：在 `styles.css` 里把品牌 token 映射成 shadcn 的语义变量；用 `@fontsource` 引入 Plus Jakarta Sans 和 JetBrains Mono；去掉横线纸纹；主题改成三态。补齐缺的基础组件：Select、Checkbox、RadioGroup、Switch、Tabs、Dialog、Sheet、Toast、Skeleton、Tooltip、Popover、Badge。
2. **全局框架**：顶栏（lockup、全局搜索、移动端抽屉）、页脚、全局提示条、错误兜底、统一 404。
3. **作品外框**：作品头部加标签页；新增 `/versions`，旧的 `/diff` 重定向过去；新增作品设置页。
4. **公开页面**：首页、探索、Overview、Context preview、Versions。
5. **创作流程**：新建、导入、编辑器（检查栏、依赖选择器）、发布对话框。
6. **贡献与账户**：贡献列表、审阅、提交；我的作品；设置（含改名）。
7. **服务端补齐与新功能**：搜索按 namespace 过滤并做作者主页；公开举报接口和举报对话框；拒绝理由字段；按 @namespace 查找用户；yank；GitHub 绑定界面。
8. **测试**：更新 Playwright 用例和截图，跑一遍 `pnpm ci:all`。

## 11. 实现与设计稿的差异

下列内容设计稿里有，但接口还没有对应字段或流程，实现时如实省略，没有编造数据：

- 作品卡片、我的作品：没有头像字段，用类型色加首字母代替。
- 作品页 Release 卡片：没有“来源”和“发布者”字段，发布者先显示 `@namespace`。
- Built on：Context IR 里只有依赖的 Release ID，版本号要逐个查询依赖作品；查不到时显示 `locked to rel_…`。
- 贡献列表：没有各状态的总数、变更数、敏感变更数和冲突标记。
- 作者主页：namespace 没有简介和加入时间；作品数只在全部加载完之后显示准确数字。
- 编辑器的 Next release：没有显示“改了几段、token 增减”，只给建议版本号和 Versions 链接。
- GitHub 绑定：只能查看、确认或解绑，不能新建；设计稿里的 “Use a different one” 没有对应接口。
- 设置：Sign-in methods 和 Your data 只做说明，没有做成按钮。
