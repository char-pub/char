# Roleplay 深度优化：第一轮实施方案

用户已确认第一轮范围；本方案的实施结果和验证边界见 [REVIEW.md](REVIEW.md)。已确定的事实、用户决定及设计取舍见 [DECISIONS.md](DECISIONS.md)。现有 1.0.0 和在线存档保持不变。

## 体验目标

玩家能够理解当前处境、与不同人物协商、按自己的意图采取行动、逐步获得信息，并在之后的对话和场景中感受到选择造成的后果。关闭页面再回来，剧情仍承接这些选择。

## 四个相互依赖的改进面

| 改进面 | 具体缺口 | 第一轮候选交付 |
|---|---|---|
| 作品 | 六个短开局，人物缺少当场诉求、对立立场和持续后果 | 将 2002 年扩为家庭谈话、核对安排、协商方案、落实第一步；补人物表达习惯、可谈条件、拒绝方式、信息和阶段结局 |
| 回合执行 | 文本 input 与 confirm/enter-scene 分离，App 没接剧情动作 | 一个输入包含候选行动、证据、确定性校验、准备上下文、生成与成功结算；失败不产生半轮剧情 |
| 渐进发现 | 可选目录为空；没有新信息出现的过程 | 少量必要常驻内容，其余为有说明和可见性约束的 fragments/groups；根据当前问题与状态选择正文 |
| 玩家界面 | 只有聊天、场景说明和角色名字/职责 | 常驻当前时间地点、在场人物与处境；按需展开人物和已知线索；回合后显示已生效后果与可继续的行动 |

人物与故事的新增私下言行始终是明确标注的叙事模拟。开局前事实与现实后来走向分别保存，避免把“后来入队”误当成玩家当前必须接受的既成事实。

## 第一章内容组织

建议以四个可回访场次、三种阶段结局和约八至十二条可发现材料形成可玩的密度。数量仅用于约束工作规模，不能替代内容审阅。

- 家庭谈话：玩家表达要保住的生活目标，追问母亲或伯父；人物回应应有不同动机和限制。
- 核对安排：按问题逐步展现教育、收入、住处和亲属责任的约束；未有史料的账目不编成真实数据。
- 协商方案：支持、拒绝和延期的模拟结果有正式状态，人物在后续对话中记得已经谈过的条件。
- 落实第一步：求学、独立生活或暂缓决定都有具体结果，允许玩家改变主意并承担相应后果。

每个 beat 和进入条件必须明确约束当前阶段。不得让 2020 年开局确认 2002 年的求学选择，也不能靠 `scene.beats` 或 `plotlines` 代替条件。

## Runtime 改动顺序

1. 修复上下文保真：官方 profile 与实际 provider 的 system 语义一致；目录估算和渲染选择同一语言变体。
2. 定义一次游玩回合：原始玩家输入先成为判断证据；候选动作只指向作者声明的目标，由 Core 验证；资料选择依据候选结果状态；正文和状态在成功后一起成为已提交结果。重复、取消、迟到结果和未知传输结果仍遵守现有存档规则。
3. 阶段结局先保存待确认提案，玩家点击明确确认后才结算；普通对话、资料发现和场景切换仍自动推进。成功的新普通回复替换或清除旧提案，失败保留，撤回确认恢复提案。
4. 接入按需内容：先验证 fragment 目录和固定选择，再接模型选择服务；拒绝、未知与低置信度不擅自扩大读取范围。`selected` 与决策说明矛盾须先处理。
5. 增加玩家展示：从已提交事实构造独立 DTO；角色目标的秘密部分、未来结局和作者变量不能直接发给浏览器。交互以对话为主，结构化选项是可选入口。
6. 扩展外部 Source 或长期记忆：仅在首章实际需要时增加相应的按回合获取、摘要验证、持久记录和恢复语义。

这些行为放在既有 Roleplay driver、选择服务和 App 中。一般编码 AgentLoop 不承担剧情执行。

## 验收场景

确定性轨迹至少覆盖同意、拒绝和悬而未决三条路线。在线模型走查另行评价人物表现和叙事质量，不能由协议 mock 替代。

| 玩家行为/故障 | 应观察到的结果 |
|---|---|
| 与母亲和伯父连续协商 | 两人表达和诉求可区分；玩家未表达的内心与决定不被代写 |
| 提问后获得一个新信息 | 先前目录/模型正文/界面没有越界暴露；获取后能解释依据并影响后续行动 |
| 明确选择并换场 | 持久状态、模型下一轮输入和界面一致；无条件强行回到历史结局的行为 |
| 模糊表达或模型低置信度 | 关键分支保持未定，仍能继续交流；必要时提出具体澄清 |
| 撤回或纠正误解 | 纠正当前局部结果，能明确说明恢复到哪里；不要求整段重玩 |
| 取消、模型无正文、网络结果未知 | 原始输入保留；不出现半轮变化，不自动重复有费用的模型请求 |
| 刷新/重启后继续 | 人物、场景、已知信息和承诺保留；不重复开局、解锁或消费事件 |
| 连续 20–30 回合 | 保留重要约定和人物差异；上下文预算有明确结果，不能静默遗忘或截断 |

除主仓测试外，跨仓变化必须打包新的不可变 SDK，用 Harness 实际安装的产物和官方 provider 投影验证；不能通过源码 alias 跳过消费者验收。
